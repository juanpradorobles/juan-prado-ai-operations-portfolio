## English

This bilingual portfolio presents Juan José Prado Robles’s work applying AI to HOA customer service (CSR), virtual assistant, and assistant manager workflows. It includes WeDo, a residential-community SaaS concept; operational documentation and SOPs; bilingual web projects; and AI-assisted email and task workflows prepared for human review.

### Tools and skills

- AI workflow: Codex for code and prototypes; Gemini for research; Claude for review and auditing; Pax for scheduling and organization.
- Operations systems: CRM, Vantaca, Avanta, and virtual desktops.
- Additional skills: SQL and databases, database security, email and task automation, Office 365, and Google Workspace.

Tools are coordinated by function, and outputs are reviewed before use. This describes AI-assisted work, not autonomous operations or AI engineering experience.

### WeDo demo and Knowledge Center

The WeDo demo is a controlled mockup. All names, records, and figures are fictional. It illustrates selected product and workflow ideas; it is not the production SaaS. This repository contains no WeDo source code or configuration, and the demo does not imply every illustrated workflow is an active integration.

The Knowledge Center page is based on the original document provided for this portfolio. It retains the document’s role-based sections, operating guidance, Vantaca workflows, scripts, templates, controls, and procedure-gap register. Organization and employee names, company email and portal details, payment mailing address, and a password example are removed or replaced with generic labels. The source file itself is not included.

**The source document labels itself “Internal Use Only” and says not to share externally. The redacted version is prepared for review and is not published yet.**

### View locally

Open `index.html` in a browser. The portfolio is one self-contained bilingual HTML file and opens in English. The selected demo and redacted Knowledge Center copy are in `demo-wedo/` and `knowledge-center-sample/`.

### Publish with GitHub Pages

The repository uses the `main` branch and root folder for GitHub Pages. After the approved files are committed, wait for the **pages build and deployment** workflow, then review the portfolio and its links at the Pages URL.
